# RadLabel

**Agentic, evidence-grounded information extraction and retrieval-augmented QA over chest X-ray radiology reports.**

[![CI](https://github.com/Vibhugupta10616/RadLabel/actions/workflows/ci.yml/badge.svg)](https://github.com/Vibhugupta10616/RadLabel/actions/workflows/ci.yml)

> Research and portfolio project. **Not a medical device and not for clinical use.** Labels describe the report text, not the X-ray image.

<!-- Screenshot of the website goes here once it is live (docs/img/results.png). -->

RadLabel turns free-text radiology reports into **structured, verifiable findings** and lets users **query a patient's report history in natural language**. An LLM extractor with schema-constrained outputs labels 13 findings; a **ReAct verifier agent** with tool calling checks every disputed label against the source text; and a **hybrid dense + sparse retrieval** layer powers **grounded, citation-checked RAG** across all uploaded reports. Everything is evaluated against expert-coded ground truth with leakage-safe cross-validation.

## Highlights

- **Evidence-grounded extraction:** schema-constrained LLM labels 13 findings with sentence-level evidence, string-matched so citations can't be hallucinated.
- **Agentic verification:** NegEx-style rule checks on every report; disagreements go to a LangGraph ReAct agent with tool calling. Each label ends *verified*, *corrected*, *suggested* or *unverified*.
- **Hybrid retrieval:** dense bi-encoder embeddings + BM25, fused with Reciprocal Rank Fusion, with negation-aware filtering.
- **RAG over a patient series:** ephemeral per-session vector index; answers grounded in retrieved sentences, every citation validated in code.
- **Negation-aware embedding fine-tuning:** contrastive training with hard negatives ("effusion" vs "no effusion"), per-fold and GPU-trained; better ranking and fewer negation mix-ups in search (see Results).
- **Rigorous evaluation:** cluster-aware stratified 5-fold CV, bootstrap CIs, paired tests, leakage tests, nDCG@10 for retrieval.
- **Production-minded:** single `run_pipeline` entry point, cached and budget-capped LLM calls, uploads never stored.

## Architecture

```
report text ─► section parser ─► LLM extractor (structured JSON, Findings + Impression)
                                          │
                     deterministic checks: negation · hedging · sections · rule second reader
                                          │
                 agree ◄──────────────────┴──────────────────► disagree
                   │                                             │
                   │                          ReAct verifier agent (tool calling)
                   ▼                                             ▼
              13 labels + evidence spans + verification state (verified / corrected / …)
                                          │
  question ─► per-session hybrid index (dense + BM25, RRF) ─► grounded LLM answer
                                                              with validated citations
```

## Results

Out-of-fold on 3,086 expert-coded reports (Indiana University chest X-ray collection), 5-fold cross-validation, 95% bootstrap confidence intervals.

<!-- summary:start: generated by `python -m eval.report`; do not edit -->

| | Macro-F1, 9 headline labels |
|---|---|
| Keyword rules (baseline) | 0.838 (0.823–0.850) |
| LLM tagger only | 0.862 (0.848–0.875) |
| **Full pipeline (tagger + checks + verifier agent)** | **0.892 (0.879–0.903)** |

- Verified labels are right far more often than unverified ones: precision **0.938 vs 0.393**.
- Only **2.9%** of reports end with any unverified label.
- Search (nDCG@10, 494 query–fold pairs): base embeddings 0.564 (0.537–0.589) → negation-aware fine-tuned **0.592 (0.565–0.618)**; reports that only mention the finding as negated drop from 14.0% to 9.7% of the top 10. The fine-tuned model is used for search.
- Questions (M10b): on 576 "Is there …?" questions about 102 dev reports 97.7% match the expert codes, and 77.0% of affirming answers cite a sentence that names the finding. Across 50 reports, searching the session answers 33.3% of questions correctly vs 48.9% with every report in the prompt, at 3.6× lower cost per request.
- Ask v2 (new batches, 50 reports): per-report retrieval coverage and a revised prompt answer 66.7% of questions correctly vs 46.7% before and 62.2% with every report in the prompt, at 0.93× the cost per request of the latter; the website uses session search with per-report coverage.

## Tech stack

**LLMs:** Azure OpenAI (gpt-4.1-mini extractor, gpt-5-mini agent), structured outputs · **Agents:** LangGraph (ReAct, tool calling) · **Retrieval:** sentence-transformers (bge-small), Qdrant, BM25, RRF · **Training:** contrastive fine-tuning with hard negatives · **Backend:** FastAPI, Postgres · **Frontend:** React, TypeScript, Tailwind, Framer Motion · **Ops:** Docker, GitHub Actions, pytest, mypy, ruff

## Run it locally

```bash
git clone https://github.com/Vibhugupta10616/RadLabel.git && cd RadLabel
cp .env.example .env          # add your Azure OpenAI endpoint and key
make setup EXTRAS=dev,eval    # Python environment and dev tools
make test                     # lint, type check, tests (no API key needed)
make data                     # downloads the IU reports (checksum-verified)
```

The website setup (`docker compose up`) is documented in [docs/SPEC.md](docs/SPEC.md) once it lands.

## Honest limits

- One dataset (Indiana University, around 2013); other hospitals write differently.
- The expert codes miss some stated findings, so scores are a lower bound.
- "Verified" means faithful to the report text, not clinically confirmed.
- Supported claim: the pipeline improves over the rule baseline and over the LLM alone **on this dataset and protocol**. Not supported: clinical reliability.
